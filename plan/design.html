二、关键机制

1. 写 = 编辑文件

人对人、agent 对 agent、人对 agent，全走同一条路：直接编辑那天的文件。没有提交、没有冲突协议、没有撤销历史（背景页决策二：接受没有）。并发编辑由文件系统与编辑器处理——一天一个文件，撞上的概率本来就小。

2. 「只点不写不留下空的日子」（照搬）

月历上点一天：有文件就在正文窗格打开；没文件显示一页空白（草稿态），写下第一行才建文件。点开看看不写，什么也不留下——不会有一堆只有日期的空文件。

3. 聚合命令：现算，不落缓存

命令做什么算法
journal.calendar { from, to, lib? }窗口（含两端最多 400 天）每天：有没有文件、假日、条目与待办数扫文件名 + 逐文件读一遍。几千个文件全读是毫秒级，不做缓存不做索引；改了文件下次现算，永远跟文件一致
journal.days { from?, to? }有内容的日子与每天统计（条数、待办、完成），外加连续天数 streaks
journal.todos { includeDone? }全库任务项：日期、文本、勾没勾；日志里的按日期倒序在前，别处没有（日志没有「别处」——这条只剩历史兼容的形状）
journal.tags {} / journal.tagged { tag }行尾标签的聚合与回看（见关键机制 6）

连续天数口径照旧：current 今天还没写就从昨天起算，今天以后的日子不算；longest 全史最长。

4. 快速记录

窗格头部那行（类型下拉：待办 / 随手记 + 输入框，回车保存）照搬：写进选中的那天的文件末尾——待办追加一行 - [ ] …，随手记追加一行文字。文件不存在就此刻建。状态栏入口同一实现。

5. mdx 渲染策略：格式全功能，渲染渐进

文件就是 mdx，想写组件、公式、表格随便写；第一版正文窗格按普通 markdown 渲染（组件行原样显示源码，见原型页）。真用到组件的那天再上 mdx 编译——文件一个字不用改，只升级渲染器。这条把「灵活」的成本限制在了渲染侧，存储侧永远是纯文本。

6. 行尾标签：写在行尾，扫出来

回看靠标签：一行末尾写 #名字，写待办、记事时顺手挂上。名字里写 / 表示层级（#仿真/MMC），打它也算打了「仿真」——查「仿真」默认连下级一起回（照旧 bn-tags 的习惯），要只看精确路径给 exact。没有名字表、没有改名命令（要批量改名就是全库文本替换，agent 或人自己做）；月历上不显示标签。

命令做什么算法
journal.tags {}全部标签按路径段组树：每个节点直接行数、连下级行数、最近日子；下级缩进在树里跟其他聚合一样现算：扫全部文件的行尾 #名字，不落缓存。大小写与全半角不归一——写什么就是什么
journal.tagged { tag, exact? }一个标签的全部行：日期、行文本、任务态、这行实际打的标签，按日期倒序——「上次 #仿真 记到哪了」就是它

不做的再确认一遍：撤销历史、标签体系（层级、标签块、改名管理——行尾 #名字 是文本不是体系）与评论、查询引擎、字段声明、提交与冲突协议——一个都没有。

三、窗格与界面的归属

  • 日志窗格（照搬旧布局，月历紧凑化）：头部「今天 / 月份导航 / 年月选择 / 快速记录行」→ 月历（紧凑格子：日期数字 + 有内容的圆点，周末与假日用颜色区分）→ 全部待办（计数徽章 + 显示已完成）。原型见 prototype.html。
  • 当天窗格：点一天打开那天的文件，渲染 mdx（第一版按 markdown）。窗格本身照旧。
  • 标签窗格：全部标签的树（/ 层级缩进、每项带行数与最近日子），点一个标签原地展开它的全部行（连下级），行上可勾待办、点日期开当天窗格。
  • 状态栏「快速记录」入口照旧，写进今天（或窗格里选中的那天）。
